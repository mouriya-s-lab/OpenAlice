## 验证与收敛

本轮的验证是可追踪的构造推导、业务语义核对、状态/事件时序推演及必要的形式证明，保留任务前提、独立输出与 Main 采纳/拒绝理由。Main 不编写代码；第二档、第三档 subagent 必要时可在抽象研究中编写测试，检验明确的表达、组合或动态语义假设是否可行，不接受独立代码测试任务，不以运行样例决定设计或以测试通过代替论证。权限不构成添加测试的要求。历史实验只作为注明范围的既有证据。文档解析与链接核对只证明可阅读，不证明设计正确。

最终设计须满足原文的停止条件：关键目标可表达；已研究旧能力有保留、修正或特化解释；关键组合和时间行为可推演；不确定性可定位；没有隐藏绕过公共契约。Main 持续推进至研究产物满足这些条件，或用户明确暂停、或查尽可用材料后确有必须由外部解决的阻塞。阶段完成、方法检查、提交推送或本地任务表勾完都不构成停手条件。

## 产物、证据与当前边界

当前主书§3–5展开核心构造、状态接受、可保存操作数、可运输D、资源与解释权，§8推演连续前缀、合流及配对；独立业务分布于§6、§10–13。原始新目标反证促成D实际解析与远端检查分离，旧消费者反证促成Instrument展开/刷新/目标保真、账户估值、CCXT公开调用与模拟权限的实质构造。event-flows、research-practice与legacy-accommodation承接相同当前关系；旧机器镜像、槽位绑定与EF覆盖仅保留为历史档案。原始24组调查及身份保持不变。各项具体反例、Main拒绝与修正见研究记录，不以文档替换或子代理通过作为验收。

原始会话提取保留用户原文及实际派工参数的物理行号，用于约束研究行为，不形成独立失败报告。既有研究记录与实验归档保留其执行身份，但被整体否定的事件流及其局部时序、形式求解均不成为本轮设计正确性的依据。当前验证是显式构造、源码回查与求值推演；未运行生产程序，也不将历史执行改称当前验证。

被整体否定的旧event stream稿、事件家族、槽位派生、EF分章和组件时序不作为设计依据。当前新的计算、结果续接、状态演化和可观察行为已从原始要求、原始UTA抽象与真实契约重新推导；新动态册不继承旧流的局部时序或实验保证。具体API实现、存储与原生履约仍是独立实施义务，不替代设计论证。

保留原始源码调查及注明执行范围的历史实验记录，不保留被否定事件流的局部内容作为设计前提。维护者接受分支后按`PLANS.md`清理计划；当前hold不表示实施许可。

## 总体验收的证据强度

| 验收对象 | 必须交付的正面说明 |
|---|---|
| 扩展与共同声明 | 作者提供哪些定义和函数，类型、parser、描述、解释及结果消费者如何从同一操作数构造；结构保证与业务正确性分开 |
| 计算与特化 | 静态/动态后继、读取组合、业务转换、失败、R/P 与 Scope 的前提和消费；业务差异不扩散为核心分支 |
| 时间与状态 | 来源接纳、投影、修订、终止、checkpoint、纯决定、提交、恢复和跨上下文交接可逐步推演 |
| 数据与控制 | 普通读取不被交易化；激活不产生授权；receipt、ack、目标满足、尝试解析和责任结案不互换 |
| 新目标与旧契约 | Order、Candle、Instrument、News/NewsGroup、动态 Provider、Agent 返回与账户/FX/历史等关键场景有实际构造；旧差异有明确处置 |
| 不确定性 | 每项指出缺的是设计关系还是具体环境证据，以及它限制哪项承诺；不要求证明无限扩展，也不留隐含绕过入口 |
| 支线禁令 | 每条有会话依据，同时写清允许的正常研究路径；禁止纠偏成为暂停、清空设计或无限审计的借口 |
