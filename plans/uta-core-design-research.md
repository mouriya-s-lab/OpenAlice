## 为什么只定粗略路线

后面的调查问题应由前一轮真正发现的表达缺口决定，而不是现在按文件、对象或消息家族分完所有工。固定 prompt、固定表格和足够长的 checklist 都不能替代研究判断。计划记录方向、当前理由、证据和下一次检查点；不预先承诺最终模型、章节数、批次规模或所有子任务。

## 首个切口与调整规则

当前主书 §5.4.1、§5.4.2 已分别给出固定及动态后继的构造，§10.1.1 给出 Controlled 派生消费者，§13.4–13.5 将它们用于 Close 与估值。不能把已写出的构造重新当成空白，也不能据局部构造存在推断连接全部成立。

首先问：**某个来源的精确事实怎样经已绑定业务函数形成 checkpoint/证据，再成为唯一持久决定及后继控制的输入？** 检查的是函数与构造关系及其在修订、重启、迟到响应时的消费，而不是先要求增加类型名。若调查指出更基础的前提缺失，回到该前提；若已有关系足够，就沿真实后继继续。

分工按任务边界变化：`bounded` 调查明确范围内的普通未知并参与局部推导；`specified` 在给定材料、定义与步骤内执行明确的关系核对；`unrestricted` 处理开放或复杂构造及需要独立判断的思考。各档均不因模型身份获得结论权威，不强迫受限档猜测超出任务契约的未知。同题不同见解允许且有价值，但不是投票；不改变操作员的模型配置。

小范围产生了可采纳构造：同一 P 的初态/支持选择、当前 checkpoint 与历史控制支持分离、原意图内部控制接纳、correction 与 Start 的共同依据消费。Main 限缩 Partial 必为 Gap、修订自动重激活及强求最小依赖闭包等外推后放行；证据与理由见[本轮研究记录](../docs/uta-capability-runtime-design/current-research.md)。扩大方向据此落在具体流算子、纯规则/组协调和旧承接一致性，而非将局部放行提升为全书验收。

扩大研究完成了filter/window/join的状态消费与后继读取回注、纯规则的共享read-set与声明级消费触点、补偿输入与组目标的关联、未命中等待的独立生命周期，以及Alice接纳后的执行/回复责任分离。完整表达链审核与目标/业务时间审核分别给出正面推导，Main继续裁决过强前提并补齐真实断裂；旧承接册仅修正当前判断，保留原始行为与来源。Z3符号归纳单独核对固定依据和Start线性化，不代替这些设计论证。

## Main 的放行责任

每次放行说明：这轮增加了什么解释；依据来自目标、当前源码、候选假设还是外部证据；共同规律在哪一层成立；真实差异如何进入；最重要的反例是否能改变候选判断；还有哪些不确定性。不能仅依据格式合规、文件数、模型一致、编译或样例通过。

下一轮只具体化当前证据支持的部分。发现前提未定时，先做能区分解释的小调查，不把前提带进大批量派发。Main 的研究放行不是维护者认可架构，更不是实现完成。

## 验证与收敛

本轮的验证是可追踪的构造推导、业务语义核对、状态/事件时序推演及必要的形式证明，保留任务前提、独立输出与 Main 采纳/拒绝理由。Main 不编写代码；第二档、第三档 subagent 必要时可在抽象研究中编写测试，检验明确的表达、组合或动态语义假设是否可行，不接受独立代码测试任务，不以运行样例决定设计或以测试通过代替论证。权限不构成添加测试的要求。历史实验只作为注明范围的既有证据。文档解析与链接核对只证明可阅读，不证明设计正确。

最终设计须满足原文的停止条件：关键目标可表达；已研究旧能力有保留、修正或特化解释；关键组合和时间行为可推演；不确定性可定位；没有隐藏绕过公共契约。Main 持续推进至研究产物满足这些条件，或用户明确暂停、或查尽可用材料后确有必须由外部解决的阻塞。阶段完成、方法检查、提交推送或本地任务表勾完都不构成停手条件。

## 总体验收的证据强度

| 验收对象 | 必须交付的正面说明 |
|---|---|
| 扩展与共同声明 | 作者提供哪些定义和函数，类型、parser、描述、解释及事件槽位如何从同一操作数构造；结构保证与业务正确性分开 |
| 计算与特化 | 静态/动态后继、读取组合、业务转换、失败、R/P 与 Scope 的前提和消费；业务差异不扩散为核心分支 |
| 时间与状态 | 来源接纳、投影、修订、终止、checkpoint、纯决定、提交、恢复和跨上下文交接可逐步推演 |
| 数据与控制 | 普通读取不被交易化；激活不产生授权；receipt、ack、目标满足、尝试解析和责任结案不互换 |
| 新目标与旧契约 | Order、Candle、Instrument、News/NewsGroup、动态 Provider、Agent 返回与账户/FX/历史等关键场景有实际构造；旧差异有明确处置 |
| 不确定性 | 每项指出缺的是设计关系还是具体环境证据，以及它限制哪项承诺；不要求证明无限扩展，也不留隐含绕过入口 |
| 支线禁令 | 每条有会话依据，同时写清允许的正常研究路径；禁止纠偏成为暂停、清空设计或无限审计的借口 |

检查失败只重开受影响的关系及其消费者，不清空全部既有成果。完成本阶段指核心设计达到上述条件，不表示生产实现、维护者接受或允许合并。分支 hold 继续有效；计划保留到维护者接受后按 PLANS.md 清理。
