# UTA抽象研究的实际校准

本页服从[方法论完整原文](../uta-capability-runtime-design.md#design-methodology)，不另建研究流程。每次开始或恢复、派工、整合前，先实际读取[历史及当前失败](current-research.md#历史会话偏离与禁令依据)及其引用证据；compact摘要不替代它们。维护者已经指出的失败不交给Main或子代理重新裁定。

当前任务仍是完整UTA核心设计。研究记录、局部构造、图或实验都不是独立终点；[活动计划](../../plans/uta-core-design-research.md)按真实缺口调整，分支hold仅限制PR与合并，不要求停止研究。

## 哪些实际试做改变了研究

### 同一结果的投影，不等于另一个产生者的行为

小范围研究先给出p的实际值、纯投影及后继，再改变产生者：另一个q可以返回相同基础值，却额外写入。这个反例让结论收紧到同一次计算的值运输，而不是继续补齐“扩展透明”的字段表。

独立核查也出现不成立的嵌套错误和重括号等式。Main没有因报告完整就接受整份证明；普通E联合也没有被强行改为阶段标签。不同视角的价值在于给出可逐步反驳的论断，不是模型多数票。

### 输出前缀迫使驱动改变

上游一次产生u、v，下游u产生并实际交付z，处理v失败。如果先纯fold整个批次、成功后才输出，z会消失。这里改变的是消费者可见前缀，不是结果类型的字段。

核查者随后把“交付未完成”写成“尚未观察”。Main限定：调用前取消可以判断本次尚未调用；调用中确认未返回，外部可能已经观察。解释取消必须定位实际边界，不能靠一个状态名消除未知。

### 独立业务例子可以迫使核心修正，但不成为核心政策

Order试做曾把完整消费者或公开入口作为外部操作数，却声称由高阶构造生成。Main要求展开：共同业务函数是什么，叶子作者提供什么，高阶函数实际构造哪些输入、工作及消费者。只改名称没有解决循环说明。

等待Order例子单独选定具体保留政策，再发现Agent答复可能早于prompt有限返回。修正的公共关系是生产之前已可见的独立接收，而不是把Question、Keep或Discard加入核心。Alice的接纳、spawn、任务结果及UTA答复接受也必须分别查实。

这说明实例可反向改变核心，不能只承担“填满预设骨架”的责任；同时核心的类型、操作数及流仍需独立说明，不能把业务名机械替换成A/B就称为抽象。

### 资源所有权必须沿真实失败分支继续存在

资源试做从三个反例开始：use失败跳过成功后继释放；返回惰性流后资源已关闭；两个借用各自关闭同一资源，先退出者破坏另一者。由此才提出实际Exit消费、受保护责任交接及单owner借用，不先引入引用计数框架。

Main随后写连接替换业务实例，独立审阅又发现新获取失败、发布前中断及并发替换会遗失责任。实例因此改为同一长寿命manager串行拥有，开始撤销旧活动资格，新成功获取受保护登记，发布与准入同一接受边界；调用请求退出不释放活动资源。身份检查防旧health覆盖，却不替代网络使用静止。

这一轮证明局部正面流不够：失败分支仍可能改变构造。它不证明整书已经通过，也不证明实际运行库满足所选中断政策。


双连续来源的两路构造与反例研究已实际区分合流和配对：交替等待阻塞另一源，取消race败者可能丢已消费值，配对要保留已持有项；容量与正在交付项共同决定接收准入。Main还修正关闭与发送检查之间的竞争，不声称关闭前已准入的IO绝不会稍后启动。不能因单源驱动成立就直接给merge/join填签名，也不能用一个成功序列代替失败与停止推演。

原始跨语言目标另行反驳“本地r与描述同源便可公开运输”的断言。有效修正是给出有限D的实际解析、编码和描述递归，再将D之外的远端检查作为真实计算消费；不是只加“不支持拒绝”。往返律还被报文/序列资源上限限定，必须在同一profile可编码的合法值域内成立。这里真正增加的是可执行构造的解释，不是再列一份schema字段目录。

## 来源事实、业务要求与核心义务不得相互冒充

- 当前IBKR等待器允许某类回调解除等待，是源码事实；对应交错在真实TWS发生，需要独立实测。
- 当前connected/degraded没有某个readable门槛，不自动证明设计必须添加该门槛；是否需要私人账户读取是业务前提。
- 当前CCXT按金额换数量先fetchTicker，是实际IO，不能称为纯编译参数转换。
- 旧IBroker不能表达查询缺席或close差异，不推出新核心必须认识公共Close或Coverage业务协议；先用实际计算和消费者分别实例化。
- 类型与编码关联成立，不证明原生承诺、业务判据、权限或结果因果成立。
- 原始问题本身也可能带有旧候选政策，例如要求所有写入先有版本化calendar、统一ReconcileBeforeRetry或某个公共ConnectionLayer。保留问题原文与身份不等于接受这些前提；须重新区分实际来源未知、具体业务需要和真正的公共关系。
