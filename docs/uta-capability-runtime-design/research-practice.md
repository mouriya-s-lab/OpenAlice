# UTA 设计研究：本轮裁决与有效实践

本记录的权威来自[方法论与边界完整原文](../uta-capability-runtime-design.md#design-methodology)。它记录实际调查怎样改变了提问、哪些论断被采纳或拒绝，以及下一轮为何值得做；不是替换原文的新方法论，也不是最终架构。

状态：已完成启动小样本、校准和第一批有限扩展。主设计、事件流、旧能力承接及原有实验归档没有被本轮重写；“现存稿件是候选”不等于丢弃它们。后续研究由[唯一活动计划](../../plans/uta-core-design-research.md)衔接，不预排完整模型、文件分工或所有后续任务。

## 现存设计的起点

主书已经有能力关联、schema 构造、计算组合、交付、纯决定、受控写入和延后激活。§13 的 rich Candle、动态外国 Provider、Candle 激活 Order 并返回 Agent 是新目标输入，不是从旧系统能否实现来决定其存在。初版的 Decision/Evolution 与效果解释关系也仍有研究价值。

需要继续论证的是这些关系如何连接、何时成立，而不是继续补对象目录。例如主书 §5.4 提出值依赖组合与 E/R/P 保持，§16.5 提出透明事件投影，旧能力调查提出 GrossNotional 和 cooldown 的批准消费边界。这些都是可检验的候选关系或政策，不因正文写了“选择”“实施规格”“accepted”就成为推导前提。

## 首轮实际改变了什么

| 轮次 | 实际做法 | Main 裁决与后果 |
|---|---|---|
| 小样本 | `bounded` 与 `specified` 对同一材料独立研究“前结果怎样决定后继” | 不放行。出现把 Candle 输入安到旧 guard、把无一致性证明说成伪造快照、把动态分支覆盖收紧为有限枚举等外推 |
| 校准 | 第二档追真实 caller/guard 状态；第三档比较明确前提下的候选解释；Main 回到源码并运行局部实验 | 分开当前事实、思想实验与候选政策。保留短路构造规律，定位 eager 状态写入；不采纳“要求上界就是授权” |
| 再对照 | 第三档比较描述范围与授权时机；第二档挑战共享解释的前提 | 只采纳有依据的部分。得到有 B 无 C、实际选择 B 的区分场景；拒绝把不同维度绑成互斥架构 |
| 有限扩展 | 两项第二档调查构造描述和风险语义；透明投影用第二档查源码、第三档做有限数值推演 | Main 独立核对并运行两个针对原样例的反例。没有按整份报告盖章，没有转成完整设计批量填表 |

这是本轮执行记录，不是以后必须复制的四轮模板。相同材料的首轮是跨模型观点对照；后续改变了材料和任务形状，是同题异法或互补调查，不冒称控制变量充分的 A/B 性能实验，也不据此排名模型。

原始任务输入、完整模型输出、拒收记录、实际脚本与输出保存在[研究证据归档](research-evidence.tar.gz)。失败报告没有改写成看似最初就通过的结论。

## 目前获得的设计判断

### 后继的描述范围与执行许可不能混为一谈

主书 §5.4 的 `A -> Query` 关系值得继续论证。要同时兑现“从声明派生描述”和值依赖的后继，需要说明哪些东西在构造时可知，哪些由运行结果选择，选择后的 binding、失败和权限如何被消费者看到。

有限实例集合、参数化 family、运行时认证的后继都是待比较的表达方式。有限业务分支不是核心特判；family 的权限上界只是要求描述，不是已经授予的许可。静态 TypeScript 不会因发现远端 schema 而长出新类型，但这不否定通过明确关联组合动态文档。

一个有效思想实验只需要两个候选后继 B/C：主体有 B 权限、没有 C 权限，前段 Q 的实际结果选择 B。若业务承诺“Q 开始前全部后继均已获准”，它会拒绝 Q；若承诺“选中后继在执行前获准”，Q 与 B 可以运行。两者都能避免未授权执行，仍有不同结果。是否选择其中一种，不能从 FP 或类型并集自动推导；也不需要假定 Q 无成本、可重试或必然写 checkpoint。

**实际反例。** 第15章归档的 `specimen/algebra.ts` 中，`combineReads` 派生 product、失败联合、资源集合和 child binding，但 `Meaning.permission` 是手传的单字符串。`specimen/catalog.ts` 只检查外层这一项。Main 用原代码创建左右两项读取、组合只声明左权限：主体直接解析右侧入口被拒绝，解析组合却成功，左右本地处理器各执行一次。

因此，现有样例没有机械保证书面的 `P1 ∪ P2`；不能用它为这条保证背书。这不是生产漏洞结论，不是静态或动态组合不可能，也没有在本轮用补一个权限判断来替代整体关系研究。

**仍需区分：** 一个 value-dependent program 在执行前对消费者承诺什么，以及执行后选中的关联如何可见。首次 descriptor 可以是有参数的稳定契约；不能武断地把“后继尚未选定”说成“根本无法描述”，也不能把描述方式与授权时机再次绑成二选一。

### 旧 guard 带来的约束在状态消费，而非否定高阶组合

当前 `createGuardPipeline` 顺序短路，同一 operation 的检查共享 context；不同 operation 会重新调用账户/仓位读取。重新调用不保证 Provider 返回不同对象或新的原子快照。`OperationGuard` 没有纯度契约，`GuardContext` 的浅层 readonly 也不是运行时冻结。

实际调用边界见 `services/uta/src/domain/trading/UnifiedTradingAccount.ts:180-205`，顺序消费与结果接纳见 `services/uta/src/domain/trading/git/TradingGit.ts:119-185,929-967`；读接口见 `packages/uta-protocol/src/types/broker.ts:553-566`。这些源码不含 Candle crossing，也未承诺组合级原子拒绝。

**实际实验。** 对真实 pipeline 注入本地读取和计数 dispatcher：两个不改变业务状态的检查共享同一 context，可以继续；测试仅额外记录 context 以核对共享，不能据此宣称现有 guard API 强制纯度。把 `CooldownGuard` 放在一个必拒检查前，第一次被后置检查拒绝，第二次被 cooldown 拒绝，dispatcher 总调用为零。`guards/cooldown.ts:15-31` 在返回允许前已经修改自身 Map。

可保留的是符合明确前提的纯判断组合；若目标要求整体拒绝不提交局部占用，则要把提议、后续可见状态与真正提交的关系说清楚。不是把每个 guard 改成新状态机，也不是推导所有规则具有同样的占用与释放语义。

GrossNotional、减仓适用性和 cooldown 从批准、派发还是原生接受开始计时，是业务政策而非 FP 定理。尤其不能照抄本轮风险报告的“已证实减仓卖单必被候选 GrossNotional 拒绝”：`docs/uta-effect-runtime-design/solutions/Guards/entries.md:326,341,350,579` 还允许声明并证明 non-increasing 的叶子为 `NotApplicable`。必须先确定这项适用关系，再计算结果。可表达某个政策，不证明它就是正确的政策。

### 结构投影与行为透明之间需要消费函数的关系

第三档给出的有限轨迹有区分力：阈值为100，先有 `(close=99,vwap=99)`，再有 `(close=99,vwap=101)`。基础消费者看 close，富值消费者改看 vwap，候选是否产生及状态就不同；即使丢弃 vwap 的基础投影总定义，基础字段也完全相同。

这个反例只说明改变谓词以后不能继续声称原来的行为透明。它不要求新增核心 Candle 类型，也不要求核心内置一个阈值 DSL。业务函数仍可以特化；透明性需要另行说明转移与投影如何相容。声明“读了哪些字段”也不是充分证明：同样只读 close、使用不同阈值的两个函数仍可产生不同轨迹。原报告对释放责任、coverage 也发生变化的断言没有相应前提，未采纳。

第二档在真实事件样例中发现了更隐蔽的消费：`FeedControlMachine.accept` 对完整事件做 `JSON.stringify` 以判断重复内容，实际读到了扩展字段。Main 执行两条独立路径，保持 eventId、sequence、基础 payload 不变，只把 vwap 从101.25改为102.25：

- 富事件先接纳：`rejected / duplicate-id-conflict`。
- 先投影再由基础机接纳：`accepted / duplicate`。

**结论边界很重要。** 这是 schema 合法但与已接纳内容冲突的输入。主书 §16.5 又将规律限定在可接纳事件上，因此本实验不推翻已接纳合法轨迹上的条件律。原 CLI 先经 rich machine 再投影，也不能据此声称它漏掉冲突。被检验的是“可任意交换接纳与投影”这个更强命题：只比较合法输出的 tag/payload，不足以证明拒绝、去重和状态消费也相容。

下一步应辨明所需保证的定义域与观察面：是已接纳轨迹的基础行为相容，还是连接纳/拒绝分类都保持。根据需要检验消费函数、状态投影和身份关系，而不是只增加更多正常帧。

## 可以固化的实践，以及不能固化的东西

### 从问题选择工作形状，而不是从档次分配固定工种

本轮第二档的真实 caller 调查和隐式去重依赖调查有价值；第三档的权限时机与 close/vwap 思想实验也产生了可用区分。两档同时出现过无证据外推。经验不是“哪档永远可信”，而是：前提已明确时可把逻辑比较交给第三档；普通源码未知交给第二档；需要开放探索或陌生外部系统时升级任务能力，不能让任何档次猜。

同题独立看法适合暴露阅读偏差；源码与逻辑互补适合分离“发生了什么”与“由此能推出什么”。实际结果决定是否换视角、补一个来源、做最小实验或扩大，不能把同一 prompt 发更多次当纠偏。

### 接受的是有依据的论断，不是模型的一整份报告

保存原始输出，再明确采纳、限缩或拒绝的部分。新要求不能被写成旧代码已经违反的事实；候选要求、当前实现、条件推论和原生证据也不能排成一个万能可信度顺序——它们回答不同问题。

本轮拒收过：从 `Promise.all` 推出原子快照承诺、从 branch coverage 推出必须枚举、从要求上界推出授权、从同字段推出同转移、漏掉 `NotApplicable` 后下数值结论。裁决须落到触发这些错误的前提与来源，不能用“存在局限”把它们掩过去。

### 实验服从问题，不让实验替设计选模型

本轮运行既有代码和归档解释器，是为了区分 eager 状态、权限传播和投影顺序；没有为方便执行而先造一套新 UTA 模型。通过或失败都只支持实际观察。一个良性样例不足以证明普遍规律；一个冲突输入也不能越过原律的定义域宣判它失败。

### 扩大的是经过检查的问题，不是尚未论证的答案

下一批给出为什么值得调查、所需材料和不可越过的证据边界即可，不预分所有字段、类型和消息。若新结果又在复述候选规则，或反例依赖未给定的前提，应退回小样本；若只是原生事实未验证，则将那项义务定位到 Provider 边界，不停止已有契约的内部推演。

这里没有普遍有效的固定 prompt、评分阈值、每批人数或完整 todolist。固化的是保留原文、动态调整分工、核对论断、允许不放行，以及把每次改变的理由留给下一位研究者。

## 验证与复现

本轮执行了真实 subagent 调查及 Main 裁决，并运行三组隔离研究程序。它们都使用本地输入，不读取交易凭据，不连接 Broker，不修改生产代码或用户状态。Node 为 v26.8.1；归档样例依赖 Effect 3.22.1、Zod 4.3.6、tsx 4.21.0。保留了工具链 DEP0205 警告，没有抑制它。

发布检查从研究归档重新解压到新目录，完整执行了三组程序，得到相同的状态残留、权限组合和投影分类结果；对已有执行目录返回 exit 2 并拒绝覆盖。另让一个新 `bounded` 研究者从落盘记录接手，它选出 Instrument 到 Candle 有限读取的一条局部调查，保留源码事实与目标承诺的区别，没有扩成全量 Provider 分工；其报告与 Main 的限缩裁决也在归档中。Markdown 实际渲染通过，14 个本地链接及方法论锚点可解析。这些是本轮可复现与可接手的证据，不是对未来不偏离的保证。

在当前研究分支 checkout 根目录，选择新的本地证据目录和新的执行目录：

```sh
mkdir -p "$EVIDENCE_DIR"
tar -xzf docs/uta-capability-runtime-design/research-evidence.tar.gz -C "$EVIDENCE_DIR"
sh "$EVIDENCE_DIR/uta-research-evidence/replay.sh" "$PWD" "$NEW_RUN_DIR"
```

`NEW_RUN_DIR` 必须尚不存在，脚本拒绝覆盖。它解压两个原实验归档，仅安装第一份锁定依赖，第二份复用相同版本的运行依赖；再执行当前 checkout 的 guard 实验和两个原样例反例。三个 `.stdout`、`.stderr` 保存实际结果，成功只表示预期研究现象重现。原始输出与任务上下文也在研究归档内，不依赖聊天或隐藏推理。

这些不是新 UTA 产品的 runtime 验收，也没有完成原生 Provider conformance、架构接受、迁移或交易能力。文档渲染与链接检查另只证明记录可被读取；后续核心设计仍按方法论原文的停止条件判断。
